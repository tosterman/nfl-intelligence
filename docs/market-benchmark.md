# Matched forecast and market errors

This implementation extends the unchanged market-pairing v1 observations into descriptive score-error accounting. A sanitized audit is now wired to the local performance page; public rollout and automatic refresh remain unverified. It is not a separately verified preregistration receipt and does not calculate betting settlement, return or CLV.

For each book, spread and total remain separate. Use the latest valid forecast published by the protocol's 24-hour entry checkpoint and a sampled market observation from the final 15 minutes before kickoff. A spread of home -3 corresponds to a market-implied home margin of +3. Compare absolute model and market errors against the same retained final result. Include tied scores. Each mean uses exactly the same games for that book/market; empty cohorts have null means, never zero error. No favorable-book selection or older-quote fallback is permitted.

Final scores must match the exact retained schedule bytes and game context, with source acquisition after kickoff and no future acquisition/edition timestamps. Every private paired record identifies its snapshot, publication receipt, quote capture/update/upload and result source. Pending results remain separate from missing or stale checkpoints. Exclusion reasons can overlap and must not be summed as unique games.

Run `python scripts/report_market_benchmark.py --export <verified-local-export>` using an authenticated retained odds export. It makes no provider requests, verifies the original pairing protocol, retains report inputs/code/captures privately, and writes the sanitized aggregate to `reviews/market-benchmark-summary.json`. Replay the resulting report with `python scripts/replay_market_benchmark.py <reportHash>`; the checker verifies dependencies and runs the pinned grader with networking blocked.

The generator now invokes that replay before replacing `data/market-benchmark.json`. A create-only writer lock prevents overlapping replacements; audit coverage, result-source acquisition and edition generation cannot move backward. The reader file is replaced atomically only after replay and diagnostic writes succeed. An interrupted or failed replacement preserves the previous reader bytes and dates. Seven publication-failure tests cover replay rejection, mismatched proof, a competing lock, coverage/source regression and atomic replacement failure. The real generation command passed this gate; 38 market-related Python tests and the three UI contract tests passed.

Independent code review found no further actionable defect in the scoped replay/lock/replacement changes. A separate invocation of the actual generator with deliberately wrong schedule bytes exited unsuccessfully and preserved all three previous artifacts exactly; see `reviews/market-benchmark-failed-refresh.json`. This is an intentional local failure exercise, not a real provider outage or remote-publication proof.

The September 11 real run used archive coverage through 00:38 UTC, not a new export. It produced zero paired games: one pre-protocol closing checkpoint, one evaluated closing checkpoint and 270 future checkpoints. The evaluated game's nine books each lack an eligible closing capture and its entry checkpoint predates activation. This is 18 excluded book/market rows, not 18 games. No capture window was widened.

Validation: 31 market-related Python tests passed, including nine new benchmark tests. Independent code review found and prompted the future-edition rejection. The retained real report replayed exactly with zero paired games and networking blocked; see `reviews/market-benchmark-replay.json`.

The local performance view validates audit chronology, reconciled counts, unique book/market rows and nullable empty-cohort means. It shows the stricter entry forecast definition separately from latest-pregame scoring, with source coverage dates, per-book reasons and distinct game versus book/market counts. Chromium and WebKit at 320px passed keyboard disclosure checks, zero document overflow and scoped axe checks. Positive paired values are fixture-tested and do not appear as real results.

## Private recovery package

`python scripts/market_benchmark_bundle.py <reportHash>` replays the pinned report, packages its declared dependency inventory and validates file hashes and bounded extraction paths. `restore` in that module writes only to a new directory and does not execute code. Explicitly run `replay_market_benchmark.py` against a trusted restored package to reproduce its calculations. Python's generated bytecode caches are excluded; they are not report dependencies.

The first package contained 1,048,696 compressed bytes. It restored into a clean temporary directory and replayed with networking blocked. The exact package was then stored privately under `market-benchmarks/` using `retain_market_report.ts <bundle> --benchmark`; byte-for-byte readback passed. A repeated invocation reused the same immutable object and preserved its original upload time. Evidence for that first package is `reviews/market-benchmark-bundle.json`; the private-retention receipt now reflects the newer combined run below.

The explicit mode keeps benchmark objects and receipts separate from earlier checkpoint audits. Independent review caught and prompted a reciprocal wrong-mode check before either receipt is modified. Its actual CLI regression covers both wrong-mode directions. Five package tests cover exact restoration, no overwrite, traversal rejection, hash mismatch, wrong kind and expansion limits. No raw capture or replay bundle was committed publicly, and no new provider odds request was made.

## Combined refresh and rollout

`python scripts/run_market_benchmark.py` uses the existing `BLOB_READ_WRITE_TOKEN` environment credential. It exports stored captures without calling the odds provider, prepares a candidate without changing the reader, replays and packages it, verifies exact private-retention identity, then performs the replay-gated atomic local replacement. A separate worker lock covers the complete sequence. Errors retain a sanitized stage report and never expose raw quote or credential output. Four runner tests cover failed export/grading/retention, replay failure, wrong retention identity, competing lock and success ordering; the full market test set now has 48 passing tests.

The real combined run completed September 11 at 19:56 UTC. It extended archive coverage through 19:55:57 UTC and stored a 1,101,365-byte private package before replacing the local audit. The report remains at zero paired games. See `reviews/market-benchmark-combined-run.json`, `reviews/market-benchmark-private-retention.json` and the matching replay receipt.

The forecast workflow includes an independent, nonfatal step gated by `MARKET_BENCHMARK_ENABLED=true`, using the existing Blob secret. The repository variable is currently unset, and the forecast workflow remains paused pending the public rollout. The recovery artifact includes sanitized benchmark/run/retention metadata, not raw private captures.
