# NFL Intelligence product and engineering design

Source of authority: founding.docx, all 31 sections. The owner authorized autonomous design, implementation, review, GitHub publication, and Vercel deployment on 2026-09-10.

## Product
Build a fast weekly NFL command center and detailed game analysis, public performance laboratory, team power ratings, methodology, and trust pages. Dark graphite, chalk typography, muted blue, generous spacing, distinct football field geometry, and compact analytical tables. Mobile exposes the same essentials with progressive detail. No gambling calls to action or fabricated confidence.

## Architecture
Next.js App Router and TypeScript render versioned static JSON generated by a Python statistical pipeline. Opponent-adjusted scoring ratings blend with historical efficiency regression. Selection uses 2021–22, residual scales use 2023, and 2024–25 is retrospective development evaluation: inspection during development consumed its original holdout status. Source retrieval timestamps, hashes, evaluation assumptions and limitations travel with the artifact. Predictions never ingest the target result, market lines, injuries or observed weather as football features.

Game output includes expected score, home margin, total, distribution interval, win probability, fair moneyline, auditable additive contributions, and separately attributed personnel, weather and historical efficiency context where verified sources exist. Missing and expired context remains explicit; these modules do not imply validated numerical adjustments. Market comparisons require trustworthy pregame price timestamps; historical closing lines can be evaluated separately but cannot masquerade as live quotes. Uncalibrated or unsupported edges are withheld.

Every generated pregame snapshot is append-only and identified by its content hash and timestamp. Publication and refresh use Git history and a checked-in ledger, refusing retroactive forecasts once kickoff passes. Historical replays are marked retrospective, never mixed with public live performance. Final-score updates must not rewrite forecasts. Empty and stale states are first-class.

## Alternatives evaluated
1. Live multi-provider database service: strongest eventual coverage, but needs paid data rights and operational secrets before reliable launch.
2. Static hand-built prediction demo: fast and visually flexible, but violates evidence and accountability requirements.
3. Reproducible statistical publishing system: chosen initial architecture. Real trained model, real results, auditable forecasts, tiny runtime attack surface, automatic scheduled refresh. Add licensed feeds through explicit timestamped interfaces.
