# Personnel snapshot pipeline — September 10, 2026

`python scripts/refresh_personnel.py` now acquires the current season's nflverse injury/practice CSV and verifies its SHA-256 and byte count against GitHub release metadata. It rejects unknown status values, duplicate player/week identities, missing player IDs, wrong seasons, unsupported game types, invalid weeks and unexpected teams. Blank game statuses remain null. Practice and game status are separate fields.

The first real capture contains 139 rows. `data/personnel.json` carries source identity, release update time, acquisition time, attribution and transformation notes. `data/personnel-sources/` retains the exact CSV compressed with deterministic gzip and a separately hashed normalized capture. Reproduction tests match normalized rows to the original bytes and validate archived capture hashes. Data is attributed to [nflverse](https://github.com/nflverse/nflverse-data/releases/tag/injuries), with the repository's [CC BY 4.0 license](https://github.com/nflverse/nflverse-data/blob/main/LICENSE.md). Our normalization and lack of individual report times are explicitly recorded.

The game-selection function requires exact season/type/week/team matching. Both acquisition and asset update must be within thirty hours and cannot be future-dated. Re-downloading an old asset does not reset its age. Current selection closes at kickoff and excludes captures acquired at/after kickoff. A missing team is returned as unknown coverage, never as a healthy roster. This function selects recent observations; it cannot prove the actual date of each practice report.

Six focused tests cover scope/status rejection, empty game statuses, missing team coverage, duplicate identities, old-asset redownloads, postgame/future exclusions and real archived-byte reproduction. No numerical model changes were made. The pipeline is not yet scheduled or consumed by the public matchup page; that integration remains the next required step. Source failures raise an error and leave the previous pointer intact, whose timestamps must be checked by consumers.

Independent code review found a postseason enum mismatch: schedules use WC/DIV/CON/SB while reports use POST. The selector now normalizes these phases and regression coverage tests all four, while excluding REG matches. Seven focused tests pass after this correction; the broader 81-test suite passed before this localized correction.
