# Discovery corrections and next product work

The sitemap omitted all 32 existing team pages. It now includes each lowercase route exactly once. Static methodology, about, privacy, responsible-use and contact pages no longer claim to have changed whenever the forecast edition changes. Data-backed routes retain the edition timestamp. Two regression tests reproduced both defects before the fix and pass afterward; TypeScript checking passes.

The HTTP verification in `sitemap-discovery.json` checks the rendered XML and every listed team route on the local server. This establishes local route availability, not search-engine indexing, ranking, traffic or public deployment.

## Next substantive additions from the founding review

An independent automated founding-scope review identified three bounded additions using retained inputs. These are recommendations, not implemented features or model endorsements:

1. Explain revisions through contribution deltas. Use retained contribution arrays only when game context and model definitions are compatible, and reconcile the components to the total forecast change. Do not infer injury or weather causes from file changes.
2. Show the eligible sportsbook snapshot side by side, including differing observation times and missing markets. Spread and total ranges should describe the captured quotes, not imply an executable consensus price or profitable edge.
3. Join verified prior usage context to personnel reports: appearance count, snap shares, historical teams, and last appearance. Preserve missing history and team-change distinctions; historical participation is not current availability or causal player value.

The review mapped these respectively to founding sections 21, 15 and 11. Each needs its own implementation and browser verification. Existing research experiments remain inconclusive and the production model should not change solely to support these explanations.
