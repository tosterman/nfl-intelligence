# Prospective score accountability

The published-before-kickoff record now retains score errors for all eligible completed games, including ties. Conditional winner accuracy, Brier and log loss continue to exclude ties. Margin and total MAE have their own all-game denominator; each 80% interval coverage measure has an explicit count of available intervals. Missing intervals are not counted as misses or successes. Log loss uses the existing retrospective clipping convention of probabilities to [1e-8, 1-1e-8].

Selection remains the latest generated valid hashed forecast with a ready public receipt between generation and kickoff. Every scored game exposes its selected fingerprint, generation timestamp, predicted/actual home margin and predicted/actual total. Later generated forecasts cannot overwrite that selected pregame result. The display links to the matchup and separates retrospective development metrics from the live record.

Six publication tests cover receipt eligibility, ties, original prediction scoring, latest forecast selection, inclusive interval boundaries, empty samples and append-only constraints. The new server-rendered page regression uses a synthetic ties-only record: it verifies the score errors, fingerprint and matchup link, and prevents a false claim that no completed forecasts exist. Independent review caught that empty-state bug before release. The synthetic record is test-only; production still has zero eligible completed games and one excluded completed game.

The live aggregate in site.json was recomputed from the existing authoritative games, ledger and receipts; no source dates or forecasts were regenerated. Local browser inspection verified the real empty state and selection-policy text. The filled state has server-rendering coverage, not a claimed real-result or physical-device visual check.
