# Odds quota availability check

The collector checks the provider's quota-free `/v4/sports/` endpoint before acquiring three US markets. It requires a successful response and a nonnegative safe-integer `x-requests-remaining` value of at least three. Missing, malformed, insufficient or failed quota responses stop acquisition. A fresh stored snapshot skips both requests; storage retries still reuse a single odds response. Both network requests reject redirects.

[Provider documentation](https://the-odds-api.com/liveapi/guides/v4/) identifies the sports endpoint as quota-free and describes remaining-credit response headers and per-region/per-market pricing. This is an availability check, not a reservation, monthly spending cap or guarantee against another caller consuming shared credits concurrently. It deliberately does not infer a reset date or subscription size. Empty odds results may cost zero, but the collector conservatively requires capacity for all three requested markets.

Seven collector tests cover the new boundary and failure states alongside reuse, authorization and exact storage readback. All 66 application tests and the production build pass.
