# Retained-edition numerical replay

The September 10 edition generated at 23:29:01.710181 UTC reproduces all 15 current snapshots exactly from its 18 retained input files. The comparison includes the entire published prediction object: expected scores, margin, total, probability, interval endpoints, sigmas, profiles and contribution explanations, plus training count and training-through date. Exact rounded values are required; no numerical tolerance hides changes in displayed values. Equivalent finite integer/float representations are allowed; booleans and nonfinite numbers cannot stand in for numeric values.

`python scripts/replay_forecast.py` performs this read-only check from the repository root and emits a report to standard output. It uses the existing deterministic inference functions without changing or invoking the acquisition/publication runner. The running engine's normalized code hash and configuration must match each supported snapshot, retained source digests must match, and schedule-derived context must agree with both snapshot and edition. Older revisions lacking compatible evidence are explicitly unreplayable. Exit 1 indicates a numerical mismatch; exit 2 indicates incomplete replay coverage. Other invalid inputs fail with an exception. No report is a publication receipt.

`python scripts/verify_numerical_replay.py` is the manual integration drill for this retained 15-snapshot edition; it requires the matching local cached inputs and writes reviews/numerical-replay.json. With HTTP and socket connection attempts blocked, it reproduced all 15 snapshots and verified that original edition, ledger, inputs and engine files remained byte-identical. Temporary copies verified that an altered expected score is detected even after the snapshot hash is recomputed, changed configuration/context and missing schedule bytes are rejected, and substituting 70–0 outcomes for same-week games on or after the cutoff leaves all 15 forecasts unchanged. This last check is a bounded cutoff test, not proof of every possible leakage path or historical data vintage.

The full Python suite initially passed 233 tests. Adversarial review then identified Python's boolean/numeric equality issue; a regression failed before the fix and both replay unit tests passed afterward, including nested booleans, nonfinite values and NumPy float compatibility. The complete manual drill passed again after the comparator fix. Production inference files were not modified. Cross-platform exact replay is not yet established; a rounding-boundary difference must be investigated rather than silently tolerated.

The final full Python suite passed 234 tests. Independent follow-up review verified both the type-aware comparator and incomplete-coverage exit behavior, with no further defect reported.

Release integration adds `--new-snapshots`: only current snapshots whose generation time equals the edition time are selected, and retained older revisions are counted as `notSelected`. An unchanged edition can therefore report zero selected snapshots without claiming they were numerically replayed. The existing publication preflight still validates forecast presence, context, ledger membership and pregame timing; this numerical check supplements it. The staged refresh workflow runs the new check before publication and retains its report in recovery artifacts. The live publisher remains paused until the release is deployed and verified.

The manual drill now also verifies a 14-new/1-retained edition and an all-retained edition. The actual release command reproduced all 15 current forecasts with zero mismatches or unreplayable selections. These are local checks; a hosted refresh executing the new gate has not yet occurred.

This advances numerical reproducibility, not predictive accuracy. Prior snapshot revisions, retrospective performance aggregates, ratings and publication authenticity are outside this check's scope. The independent uncertainty-table review also found no actionable defect in a439f9f.
