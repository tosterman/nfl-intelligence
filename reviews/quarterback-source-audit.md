The [source dictionary](https://nflreadr.nflverse.com/articles/dictionary_depth_charts.html) identifies `dt` as the record loading time and rank as position-slot-specific. It does not establish team announcement time, game availability or a confirmed starting lineup. Different formation groups can contain different slots. The research selection groups the newest snapshot by team using every position; it then inspects quarterback rows within that snapshot. It does not select the newest quarterback row independently, which could incorrectly resurrect an old role after a newer incomplete snapshot.

`scripts/depth_chart.py` selects records strictly before a timezone-aware cutoff. It rejects stale snapshots, duplicate ranks within formation/slot, missing player IDs and conflicting rank-one identities. No eligible snapshot returns unknown. Five deterministic tests cover cutoff exclusion, unsorted rows, new snapshots without quarterbacks, stale/missing snapshots and ambiguity. Running the helper on the verified real file resolved all 32 teams; exact outputs are retained in `quarterback-source-audit.json`.

## Next model step

Independent review reproduced a contradictory rank case: one player assigned both rank one and two in the same formation/slot. Selection now rejects repeated player identity within that scope, and the regression case passes. Reuse of an identical player across different formation groups remains allowed when top-ranked identities agree.

This source makes a role-history and player-ID join feasible. Before numerical integration, acquire and verify the relevant historical seasons, join prior-only quarterback performance, distinguish offseason roster transitions from in-season role changes, and compare with the unchanged team baseline using time-separated evaluation. A listed first quarterback is not necessarily the game starter; that uncertainty must remain visible in any eventual UI and model treatment.
