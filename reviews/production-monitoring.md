# Production freshness monitoring — 2026-09-10

`Check production data health` runs hourly at minute 47 UTC and can be manually dispatched. It probes the public forecast and odds health endpoints without sending analytics events, fetching sportsbook data, changing forecasts or requiring secrets. Each probe has a ten-second HTTP timeout and one retry after two seconds; redirects fail rather than being followed to a login or unrelated page. The two probes run concurrently.

The checker requires HTTP 200 plus the expected health payload. It independently recomputes acquisition ages from timezone-aware timestamps. Forecast checks require the model edition, schedule/results and the exact efficiency pair for the endpoint's explicit season (season minus one and season). The season must be the current or preceding calendar year. All timestamps must remain inside the thirty-hour window, with the existing five-minute clock tolerance. Odds must have a valid acquisition no older than six hours and no future timestamp. Rounded displayed ages and a claimed status alone cannot make stale data pass. Missing identities, malformed payloads and bad source fingerprints fail closed.

A failed endpoint makes the process/job fail. A sanitized evidence file retains each attempt, its observation time, status code and bounded reason. The workflow uploads that file even after failure and retains it fourteen days. GitHub Actions provides failure visibility under the owner's notification settings; delivery of email/push notifications has not been independently verified. This is monitoring hosted on the same scheduler as collection, not an independent external uptime service. GitHub outages, delayed/dropped schedules or disabled workflows can affect both. No uptime SLA or full sportsbook coverage is claimed.

Local tests reject stale timestamps behind claimed green responses, incomplete checks, future/old odds, implausible efficiency years and bad HTTP statuses. A real local HTTP failure drill served 503 for forecasts and a valid odds response: the checker retried, returned exit code 1, and retained both failed attempts alongside the healthy odds check. The live read-only probe passed both production endpoints on September 10. The clock-triggered workflow still requires sustained observation.
