# Scheduled odds collection — 2026-09-10

The current architecture supersedes the traffic-driven design in `odds-archive.md`. All page views, including development and preview, read private stored snapshots; none call the odds provider. Only the production-only authenticated POST `/api/collect-odds` acquires provider data. GitHub's `Collect and verify odds` workflow calls it at 01:17, 06:17, 11:17, 16:17 and 21:17 UTC, or by manual dispatch. The shared collection secret is separate from the provider and storage credentials, which stay in Vercel. No credential is placed in a request URL or workflow output. Preview without storage credentials displays unavailable quotes.

The worker checks storage first and skips acquisition when the published snapshot is under three hours old. Otherwise it acquires one three-market response, normalizes it, and retries storage up to three times using those same bytes. A timestamp/hash archive is written without overwrites before the private mutable latest pointer advances. Retry after an uncertain upload accepts only exactly matching stored bytes. Readback verifies the pointer, archive content hash and equality to the just-published normalized feed. Successful capture invalidates the site's odds cache immediately. A 15-minute cache bounds normal storage reads; six-hour quote expiry remains unchanged.

`/api/odds-status` exposes only acquisition health, age and timestamp, returning 503 for stale, missing, future or unreadable snapshots. This is acquisition health, not a claim that every game/bookmaker has quotes. The workflow fails if collection or readback fails. GitHub's existing workflow-failure notification settings apply; no custom email/Slack service or independent missed-run alert is configured. The endpoint is available to monitoring tools. No raw feed download endpoint is exposed.

Five three-credit acquisitions/day nominally consume 450 credits in 30 days (465 in 31), within the existing 500-credit plan before manual runs, retries after process loss, historical tests or other account consumers. Page views no longer add provider calls. This is not a hard account-wide budget cap. The scheduler serializes its jobs, but the endpoint does not implement a distributed lock for concurrent authorized callers. Invoke through the workflow. GitHub schedules can be delayed or dropped; this is not continuous odds, a guaranteed SLA, or closing-line coverage. Operational references: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule and https://vercel.com/docs/vercel-blob/using-blob-sdk .

Review resolved predictable six-hour boundary gaps by moving to four/five-hour scheduled intervals and immediate cache expiry, strengthened readback to exact content hashes, and removed provider requests from preview/development. Thirty-two application tests and the production build passed before deployment. A later health regression check also ensures failed reads never masquerade as a new acquisition timestamp.
